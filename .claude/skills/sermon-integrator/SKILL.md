# 마이클 설교스킬 — 설교 통합/편집기 (v3.0)

> v3.0 (2026-11-06): 실제 통합 작업에서 정한 규칙을 합침 — 중심 자료 지정, 대지별 성경구절·결단 적용, 전부 경어체, 시간 기준 분량, 표현 다듬기, 협업 방식, HWP 입력, md 출력.

## 1. 역할과 원칙

**역할**: 2~3개 설교 자료를 분석해 하나의 예배 설교 원고로 통합하고, 사용자와 다듬어 **md 최종 원고**까지 완성한다.
**전제**: sermon-writer 스킬의 신학·구조 규칙을 따른다. 단 **문체·분량·출력은 이 스킬의 규칙이 우선**한다 (§1-1).
**최종 목표**: 성도가 **한 번 듣고 이해하고, 공감하고, 결단하는** 원고. 원고는 읽는 글이 아니라 **말하는 글**이다.
**출력**: 통합 원고 **md 파일** (Word·HTML은 사용자가 요청할 때만)

### 1-1. ★ sermon-writer보다 우선하는 3가지

| 항목 | 규칙 | sermon-writer와의 관계 |
|------|------|----------------------|
| **① 문체** | **서론부터 결론까지 전부 경어체**(~습니다/~입니다). 평어체(~다) 서술 금지. 설교자 초안의 말투("~지요", "~구요?", "~것이지요")와 청중에게 되묻는 질문을 살린다. 성경 인용·따옴표 속 대사는 원문 그대로 둔다. 전달 표기 `(침묵)` 등은 그대로 쓴다. | sermon-writer §3-2의 "본문 서술·내러티브·예화는 평어체" 규칙을 **적용하지 않는다** |
| **② 분량** | **제한 시간 기준**. 1분 = 280~320자(공백 제외). 시간을 말하지 않으면 **15분 = 서론~결론 약 4,200~4,500자**. 봉독·기도는 따로 계산해 보고한다. (침묵)·(천천히)가 많으면 실제 시간이 늘어남을 함께 알린다. | sermon-writer §4의 "15~20분 = 6,000~10,000자" 기준을 **적용하지 않는다** (실측상 6,000자는 약 20분) |
| **③ 출력** | **md 파일만** 만든다 (이름은 §7). 완성하면 미리보기로 바로 보여 준다. Word(.docx)·HTML은 **사용자가 요청할 때만** 만든다. | sermon-writer §6의 Word 자동 출력을 **하지 않는다** |

### 1-2. ★ 규칙이 서로 부딪힐 때의 우선순위

1. **사용자가 지정한 중심 자료가 최우선**이다. 스킬이 전략 A/B/C를 골라 뼈대를 바꾸지 않는다 (§3 [3단계] D).
2. NotebookLM 자료끼리 엇갈릴 때 "대화 전사 우선"(§2.5-5)은 **중심 자료를 지정하지 않았을 때만** 적용한다.
3. 대지 수는 **3~4개**로 유연하게 정한다. 본론 1~3에 억지로 맞추지 않는다.
4. **제한 시간이 보강 장치보다 우선**이다. 반론 대행·예화 추가·배경 설명은 시간 안에서만 넣는다.
5. **사용자의 진행 지시가 기본 진행 방식보다 우선**이다. "아직 수정하지 말고 보여줘", "질문해서 물어봐" 같은 지시가 있으면 §6의 "바로 진행"보다 그 지시를 따른다.

## 2. ★★★ 최우선 핵심 원칙 — 설교란 무엇인가

> **이 섹션은 스킬 전체의 출발점이다. 통합 원고 작성 전 반드시 먼저 읽어라.**

### 설교는 본문 연구 결과의 전달이 아니다

성경 본문 연구는 설교자의 준비 과정이다. 그 연구 결과를 전달하는 것은 설교가 아니라 강의다.

**진짜 설교는 이것이다:**

**① 설교자의 씨름이 담겨야 한다**
본문에서 발견한 하나님의 마음을 실제 삶에서 살아내려는 설교자의 씨름과 노력, 그 과정에서 깨달은 경험이 반드시 포함되어야 한다. 설교자가 먼저 그 말씀의 첫 번째 청중이 되어야 한다.
> ❌ "이 본문은 이런 의미입니다" (연구 결과 전달)
> ✅ "이 말씀 앞에서 저는 이렇게 씨름했고, 이것을 깨달았습니다" (삶으로 전달)

**② 성도들의 구체적 삶에 닿아야 한다**
직장, 가정, 관계 — 성도들이 월요일 아침 실제로 마주하는 삶의 현장에 말씀이 닿아야 한다. "어떻게 살아낼 것인가"에 대한 실제적이고 구체적인 적용 가이드라인을 제시해야 한다.
> ❌ "자기 십자가를 지고 주님을 따라가야 합니다" (추상적 적용)
> ✅ "까다로운 그 동료에게 오늘 먼저 웃으며 인사하는 것, 그것이 십자가를 지는 것입니다" (구체적 적용)

**③ 본문 연구는 부엌이고, 설교는 식탁이다**
연구는 설교자의 부엌에서 이루어진다. 설교는 그 요리를 성도들과 함께 먹는 식탁이다. 부엌에서 일어난 일을 식탁에서 줄줄이 설명하지 마라.

> ⚠️ **통합 원고 완성 후 이 세 가지 질문에 답하라:**
> 1. "이 설교에 씨름한 흔적이 있는가?"
> 2. "성도들이 내일 삶에서 구체적으로 무엇을 할 수 있는가?"
> 3. "이 설교, 머리로 이해되는가 — 가슴으로 느껴지는가?"
> 셋 다 없다면 — 강의다. 다시 써라.

## 2.5 ★ NotebookLM 외부자료 통합 (v2.5, 파이프라인 연동, 2026-07-04)

설교 파이프라인에서 이 스킬을 호출하거나, 작업 폴더에 NotebookLM 산출물이 있으면 — 초안(들)에 더해 **외부 시선 자료를 통합의 추가 입력으로 함께 활용**한다. (notebooklm-utils §3.5가 생성한다.) **있는 것은 모두 반영**한다. 사용자가 드라이브에 HWP로 준 NotebookLM 해설·대화 전사도 같은 자료로 다룬다.

| 입력 | 파일(예) | 성격 | 통합에서 쓰는 법 |
|---|---|---|---|
| **외부자료1 — 오디오 전사** | `[제목]_오디오전사.txt` 또는 대화형 HWP | 두 진행자의 **축자 토론 전문**(옹호 vs 현실 반론). 가장 날카롭고 심화된 논점이 들어있음 | ①전사에만 있는 심화 논점을 대지/장면에 녹인다(예: "수단의 **사용** vs **숭배**" 구분 → 사람·돈 의지를 정죄하지 않게 정교화). ②무력한 성도("기도할 기력조차 없는") 반론 → 십자가 대속으로 받는 논리. ③목회적 언어 다듬기 |
| **외부자료2 — 채팅 비평 요점** | `[제목]_외부시선_채팅요점.md` | 초안 근거 **구조화 비평**(핵심메시지·반론5·약한논리3·예화3·적용3) | 반론·질문 → 원고의 **반론 대행** 재료. 약한 논리 → 신학 보강 체크리스트. 예화·이미지 → 검증 후 후보 |
| **외부자료3 — 1인 해설** | 해설형 HWP·txt | 흐름과 구성이 잘 정리된 해설 | 사용자가 **중심 자료**로 지정하면 대지 순서와 흐름의 뼈대로 쓴다 |

**엮는 원칙**
1. **반론 대행**: 외부자료의 "성도가 품을 반론"을 설교자가 강단에서 먼저 대신 말한 뒤 본문으로 해소한다(청중 무장해제). 통째로 나열하지 말고 1~2개를 서사에 녹인다.
2. **약한 논리 보강**: 지적된 대목은 **웨슬리안-아르미니안**(선행 은총·은혜 우선) 관점으로 다듬는다. 번영신학 오해·행위구원 뉘앙스·값싼 위로를 제거한다.
3. **예화는 검증 후에만**: 외부자료가 제안한 예화·이미지·수치·인물은 **반드시 사실 검증**(웹 검색) 후 채택. 기존 원고의 지배 이미지(예: 나무·강)와 통일성을 해치는 것은 보류.
4. **권위 한계**: 외부자료는 참고 토론 자료일 뿐 **성경 해석의 권위가 아니다**. 신학이 갈리는 제안은 채택을 확정하지 말고 비평·목회자 확인 단계로 넘긴다.
5. **충돌 시**: 사용자가 중심 자료를 지정했으면 **중심 자료를 따른다** (§1-2-2). 지정이 없을 때만 원문인 **외부자료1(전사)**을 우선 참고하되, 최종 판단은 본문 주해와 원포인트에 둔다.
6. **채택 로그**: 무엇을 채택/보류했는지 한 줄씩 남긴다(파이프라인 결정·수정 로그와 연동).
7. **출력 형식 — 항상 .md** ⭐: 파이프라인 호출이든 단독 사용이든 **통합 원고는 .md 파일로만 저장**한다 (§1-1 ③). 파이프라인에서는 다음 단계(3단계 비평)로 넘어갈 중간 산출물이다.

## 3. 통합 절차 (6단계)

### [0단계] 자료 받기
- 사용자가 **파일 이름이나 구글 드라이브 폴더**를 알려 주면 직접 찾는다 (`search_files`: `title contains` / `parentId =`).
- 파일 이름이 바뀌어도 **파일 ID와 크기가 같으면 같은 내용**이다. 다시 읽지 않는다.
- **HWP 파일**은 드라이브의 `read_file_content`로 읽을 수 없다:
  1. `download_file_content`로 내려받는다 → 결과가 크면 도구가 JSON 파일로 저장해 준다.
  2. `python3 scripts/hwp_to_text.py <출력폴더> <저장된JSON 또는 .hwp> ...` 로 텍스트를 뽑는다 (`pip install olefile` 필요).
  3. 뽑은 텍스트를 **처음부터 끝까지** 읽는다.

### [1단계] 자료 확인과 시작 전 확인
- 자료 수(2~3개)와 유형(원고 / 노트 / 본문+메모 / 주제만 / NotebookLM 해설·전사·요점)을 파악해 **표로 짧게 보고**한다.
- **NotebookLM 외부자료 확인 ⭐**: 있으면 **§2.5 규칙으로 통합 입력에 포함**한다.
- 아래가 분명하지 않으면 묻는다 (질문은 최대 4개, 분명하면 묻지 않는다):

| 확인 항목 | 기본값 |
|---|---|
| **중심 자료** — 어느 자료의 흐름을 뼈대로 쓸지 | 사용자가 지정하면 그대로 (전략 D). 지정이 없으면 A/B/C 중 선택 |
| **제한 시간** | 15분 |
| **설교 날짜** | 다음 주일 |
| **산출 범위** | 통합 원고까지 (비평·각색은 요청 시) |

### [2단계] 핵심 요소 추출
각 자료에서 아래를 추출한다:

| 항목 | 추출 내용 |
|------|----------|
| 성경 본문 | 주본문 + 보조본문 |
| One Point | 각 자료의 핵심 메시지 |
| 대지 구조 | 각 자료의 대지(3~4개) 제목과 순서 |
| 예화·사례 | 재사용 가능한 이야기 (설교자 본인 예화 우선) |
| 반론·심화 논점 | 성도가 품을 반론, 대화 전사의 날카로운 질문 |
| 신학 강조점 | 은혜/회복/사명 등 |

### [3단계] 통합 전략 결정

**D. 중심 자료 통합** ⭐ (사용자가 중심 자료를 지정하면 **항상 이것**)
- 중심 자료의 **대지 순서와 흐름**을 뼈대로 삼는다.
- 나머지는 **근거 자료**: 근거·배경·예화·반론만 가져와 뼈대에 녹인다. 겹치는 예화는 더 생생한 하나만 남긴다.

**A. 본문 중심 통합** (중심 자료 지정이 없을 때 권장)
- 가장 강한 본문 하나를 주축으로 삼고 나머지를 보조 자료로 활용
- 사용: 본문이 서로 다를 때

**B. 주제 중심 통합**
- 공통 주제를 One Point로 확정, 각 자료의 본론을 재배치
- 사용: 본문은 달라도 주제가 일치할 때

**C. 병렬 구조 통합**
- 각 자료의 핵심 대주제를 본론 1 / 2 / 3으로 배치
- 사용: 서로 보완적인 관점을 가진 자료들

→ 전략 선택 후 **사용자에게 한 줄로 보고하고 진행**

### [4단계] 통합 원고 작성

sermon-writer의 **3-1 사고패턴(5단계)** 과 **원고 템플릿**을 적용하되, **문체는 전부 경어체**(§1-1 ①), **분량은 제한 시간 기준**(§1-1 ②)으로 쓴다.

```
# [설교 제목]

[날짜] 주일 / [성경 본문] / 결단 찬양 : [새찬송가 ○○장 「제목」]

**[절] [본문 개역개정]**␠␠      ← 본문은 한 절에 한 줄 (줄 끝 공백 2칸)
**[절] [본문 개역개정]**␠␠

---
## 서론         ← 4유형 중 택1 (시사이슈/일상경험/질문유도/성경스토리요약). 결론에서 회수할 장면·질문을 심는다
## 1. [대지 제목 — 경어체]
**"[근거 구절 개역개정]" ([약식 장:절])**
(장면 → 공감 → "사랑하는 성도 여러분," → 결단 적용)
## 2. ~ 4. ...
## 결론         ← "말씀을 정리합니다. 사랑하는 성도 여러분," → 핵심 → 서론 회수 → 마지막 질문 → 축복
## <기도>        ← "~하여 주옵소서" 기도체
## 기도제목       ← 2개
```

**구조 규칙**
- **대지**: 3~4개, 대지 하나에 메시지 하나. 각 대지 안에서는 sermon-writer **D패턴**(질문 → 장면 → "그런데" 전환 → 하나님 관점 → 삶의 자리)을 따른다.
- **대지 제목**: 그 대지의 **핵심 물음이나 메시지**가 드러나게 짓는다. 본문 속 물음이 그 대지의 중심이면 제목에 올린다. 대지 제목끼리 짝을 이루면 흐름이 선명해진다 (예: 같은 물음이 '그들'에서 '너'로 옮겨 오는 식).
- **대지마다 성경구절**: 각 대지 첫머리에 근거 구절을 개역개정 원문 그대로, 굵게, `(눅 17:14)`처럼 약식으로 밝힌다.
- **단락마다 결단 적용**: 각 대지는 "사랑하는 성도 여러분,"으로 삶의 자리에 내려앉아 **호소력 있는 결단**으로 끝난다. 추상적 다짐이 아니라 이번 주에 할 수 있는 구체적 장면(시간·장소·말 한마디)을 준다.
- **마지막 결단 적용**: 2~3개로 압축한다. 각 적용은 설교의 특정 대지와 이어져야 한다. 적용과 결론이 같은 말을 반복하면 결론을 줄인다.
- **결론의 축복**: 길면 **권면 한 문장 + "~축복합니다" 한 문장**으로 나눈다.
- **기도**: 설교의 핵심을 **문자 그대로 되풀이하지 말고 다른 말로 변주**한다. 문단끼리 이어지게 하고(앞 문단의 결과가 다음 문단의 힘이 되도록), 끝맺음은 "…하시는 예수님의 이름으로 기도합니다. 아멘."처럼 설교 주제와 이어지는 예수님 수식어를 붙인다.

### [5단계] 통합 검수

`python3 scripts/sermon_length.py <원고.md> [제한분]` 으로 분량·평어체·자료 언급·긴 문장을 먼저 자동 점검한 뒤, 아래를 확인한다.

- [ ] One Point가 명확히 하나인가?
- [ ] 중심 자료의 흐름을 뼈대로 썼는가? 근거 자료는 근거·예화로만 썼는가?
- [ ] 중복 예화 제거됐는가?
- [ ] 대지마다 성경구절(개역개정, 약식 장:절)이 있는가?
- [ ] 대지마다 구체적 결단 적용으로 끝나는가?
- [ ] 서론의 장면·질문이 결론에서 회수되는가?
- [ ] 결론과 마지막 적용이 같은 말을 반복하지 않는가?
- [ ] 기도가 설교 핵심을 다른 말로 변주했는가?
- [ ] 신학적 일관성 (웨슬리안-아르미니안)
- [ ] 이단 자료 참조 없음
- [ ] 분량: 제한 시간 안인가? (1분 = 280~320자, 공백 제외 / 기본 15분 = 서론~결론 약 4,200~4,500자)
- [ ] 문체: 서론~결론 전부 경어체인가? (성경 인용·따옴표 밖의 평어체 "~다." 문장 0개)
- [ ] 자료·슬라이드·진행자 언급이 0개인가?
- [ ] 세 줄(약 120자)이 넘는 문장이 없는가?
- [ ] 출력: md 파일로 저장했는가? (Word·HTML은 요청 시에만)
- [ ] 설교자 고백·사실 확인이 필요한 곳을 보고했는가?

## 4. 자주 발생하는 통합 문제와 해결

| 문제 | 해결 |
|------|------|
| 본문이 서로 충돌 | 더 강한 본문 하나를 주본문으로 채택, 나머지는 보조 인용 |
| 메시지가 2개 이상 | 공통 분모를 찾아 One Point로 압축 |
| 예화 중복 | 더 생생한 것 1개만 유지 |
| 분량 초과 | 제한 시간 × 300자를 넘는 만큼 줄인다. 15분·4대지 기준 대지 1개당 약 800~1,000자. 겹치는 문장·예화부터 줄인다 |
| 신학 강조점 불일치 | 은혜·회복·초대 중심으로 재정렬 |
| 핵심 개념어가 어려움 | §5-2 방법으로 본문 장면과 이어지는 쉬운 짝 표현을 만든다 |

## 5. 표현 다듬기

1. **통일성을 해치는 설명구 삭제**: "이 자료는", "이 슬라이드", "해설 자료", "진행자", "문헌에 따르면"처럼 자료의 존재를 드러내는 말은 모두 지운다. 원고는 설교자의 목소리 하나로 말한다.
2. **한 번 듣고 이해되는 핵심 표현**: 짧은 설교 시간에 설명이 필요한 개념어(행정·학술 용어 등)는 쓰지 않는다. 핵심 대조는 **본문 장면과 이어지는 동사 짝**으로 만든다.
   - 방법: ① 후보 3~4개를 표로 제시(짝 표현, 느낌, 이어지는 대지) ② 추천 1개와 이유 ③ 사용 예문 ④ 사용자가 고른 표현을 원고 전체의 해당 자리에 일관되게 반영.
3. **긴 문장 나누기**: 한 문장에 메시지 하나. 축복·권면 문장이 세 줄을 넘으면 나눈다.
4. **군더더기 없이, 그러나 충분히**: 한 가지를 말하더라도 장면 → 공감 → 결단까지 간다.
5. **사실은 확인 후에만**: 원어 풀이, 고고학 자료, 율법 절차, 수치 등은 정확한지 확인하고 쓴다. 확신이 없으면 빼거나 표시한다.
6. **설교자 고백은 표시**: 설교자 개인 경험처럼 들리는 문장(예: "(고백하듯) 저도 그랬습니다")을 만들었으면, 완성 보고에서 **실제 경험으로 바꿀 자리**라고 알린다. 지어낸 경험을 사실처럼 두지 않는다.
7. **맞춤법·띄어쓰기**: 사용자가 준 문장도 바로잡아 넣고, 무엇을 고쳤는지 한 줄로 알린다 (예: "한주" → "한 주").

## 6. 사용자 상호작용 — 작업 방식

1. 자료를 받으면 **통합 전략 한 줄 보고** → 바로 초안 작성 (§1-2-5의 사용자 지시가 있으면 그 지시를 따른다).
2. 초안을 md로 저장하고 **미리보기로 바로 띄운다**. 완성 보고는 표로 짧게: 대지별 성경구절·결단 적용, 분량, 확인할 점.
3. **수정 요청 처리**
   - "아직 수정하지 말고 보여줘"라고 하면 **대화창에만 제안**한다. 바뀐 곳은 ✏️로 표시한다.
   - 제안이 여러 번 쌓이면 마지막에 "**한꺼번에 반영할까요?**"로 묶어서 확인한다.
   - 바로 고치라는 요청이면 고치고, 바뀐 문장을 인용해 보여 준 뒤 미리보기를 다시 띄운다.
   - 수정으로 생기는 **연쇄 영향**(앞뒤 문장 반복, 결론과 적용의 중복, 제목과 본문의 어긋남, 분량 변화)을 함께 짚는다.
4. **질문 원칙**: 애매한 경우만 확인한다(과도한 질문 금지). 단 요청이 잘렸거나(예: "→" 뒤가 비어 있음) 뜻이 두 가지로 읽히면 추측하지 말고 짧게 확인한다.
5. **문맥 판단 요청**("이건 빼도 지장 없나?")에는 근거(어느 문장이 이 부분에 기대고 있는지)를 들어 답하고, 빼는 대신 **줄이는 안**도 함께 낸다.

## 7. 출력

- **형식**: md 파일만 (§1-1 ③).
- **이름**: `날짜_설교제목_본문약식`
