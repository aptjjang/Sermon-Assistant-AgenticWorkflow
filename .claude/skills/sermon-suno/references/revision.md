# 수정 모드 — 들어 본 뒤 가사 고치기

수노에서 곡을 만든 뒤, 멜로디를 지키면서 가사를 고치는 절차다.
수노 조작(구간 교체·커버)은 사용자가 한다. 이 스킬은 **붙여 넣을 수정 가사**와 **어느 기능을 쓸지**를 준다.

## 1. 네 가지 원칙

1. **글자 수를 지킨다.** 고친 줄은 원래 줄과 글자 수가 같거나 1자 차이여야 한다. 그보다 달라지면 그 구간의 멜로디가 바뀐다.
2. **가사만 고쳐 처음부터 다시 생성하지 않는다.** 그러면 멜로디가 완전히 새로 나온다. 마음에 든 멜로디는 구간 교체나 커버로 지킨다.
3. **후렴을 고치면 모든 후렴을 똑같이 고친다.** 후렴이 번번이 달라지면 따라 부를 수 없다.
4. **태그를 더하기 전에 가사 모양을 본다.** 몰림·늘어짐은 대부분 글자 수 문제다.

고칠 때마다 묻는다: **처음 온 사람도 두 번째 후렴부터 따라 부를 수 있는가.**

## 2. 사용자에게서 받을 것

- 어느 줄인가 (예: "2절 셋째 줄")
- 어떻게 들리는가 (몰린다 / 늘어진다 / 발음이 틀리다 / 말이 어색하다 / 따라 부르기 어렵다)
- 그 곡에 넣은 가사가 대화에 없으면 가사 전체

증상을 말하지 않고 "어색해"라고만 하면, 묻지 말고 글자 수·받침·줄 끝 소리를 먼저 점검해 가장 그럴듯한 원인으로 수정안을 낸다.

## 3. 증상 → 처방

| 들리는 문제 | 흔한 원인 | 처방 | 글자 수 |
|---|---|---|---|
| 줄 끝이 랩처럼 **몰린다** | 그 줄의 글자가 너무 많다 | 글자를 3분의 1쯤 덜어낸다. 태그를 더하지 않는다 | **줄어든다**(예외 — 아래 §4) |
| 한 글자가 길게 **늘어진다** | 글자가 모자라거나, 긴 음에 받침이 걸렸다 | 1자를 더하거나 줄 끝을 열린 소리로 바꾼다 | ±1 |
| **발음이 틀리다**, 뭉개진다 | 받침이 몰렸거나 한자어 교리어 | 소리 나는 대로 한글을 고쳐 쓴다. 교리어는 풀어 쓴다. 소괄호로 발음을 적지 않는다 | 같게 |
| 엉뚱한 **메아리**가 따라 나온다 | 가사에 소괄호가 있다 | 소괄호를 지운다 | 같게 |
| 말이 **딱딱하다**, 설명처럼 들린다 | '-입니다' 어미, 주장하는 문장 | 고백 어미('-네, -요')로, 장면으로 바꾼다 | ±1 |
| 후렴이 **부를 때마다 다르다** | 후렴 글자가 서로 다르다 | 모든 후렴을 같은 글자로 맞춘다 | 같게 |
| **따라 부르기 어렵다** | 후렴이 길거나 낱말이 어렵다 | 후렴을 4줄 이하·쉬운 말로. 제목을 첫 줄이나 끝 줄에 | 구간 전체를 다시 |
| 곡이 **끝나지 않고** 군소리가 붙는다 | `[End]`가 없다 | 맨 끝에 `[End]`를 넣는다 | — |
| 마지막 후렴이 **올라가지 않는다** | 전조 지시는 잘 듣지 않는다 | 여러 번 생성해 고른다. Style에 `half-step key change on final chorus` | — |
| 보컬이 **밋밋하다** | 모델 버전 차이 | 같은 입력으로 다른 버전과 비교한다 | — |

## 4. 글자 수를 못 지키는 경우

- **몰리는 줄**은 글자를 줄이는 것이 처방이다. 이때는 "이 줄은 글자 수가 줄어서 그 구간의 멜로디가 새로 나온다"고 알리고 구간 교체를 권한다.
- **1절과 2절이 같은 선율**을 쓰므로, 1절 줄을 줄였으면 2절의 같은 줄도 맞춰 줄인다.
- **후렴 구조를 바꾸는 수정**(줄 수가 달라짐)은 구간 교체로 안 된다. 전체를 다시 생성해야 한다고 알린다.

## 5. 어느 기능을 쓰는가

| 고칠 범위 | 수노 기능 | 지켜지는 것 |
|---|---|---|
| 한 구간(대략 10~30초)의 한두 줄 | **구간 교체 (Replace Section)** | 나머지 구간의 멜로디와 반주 |
| 여러 군데, 또는 보컬·스타일까지 | **커버 (Cover)** | 곡 전체의 선율 흐름 |
| 길이가 모자람 | 이어 만들기 (Extend) | 앞부분 전체 |
| 구조나 후렴을 통째로 바꿈 | 다시 생성 | 없음 — 새 멜로디 |

- 구간 교체는 보통 유료 요금제에서 쓴다.
- 메뉴 이름과 위치는 자주 바뀐다. "화면에서 이름이 조금 다를 수 있다"고 한 줄로 알린다.

## 6. 수정안 내는 법

1. 대화에 마지막으로 보여 준 가사(현재 가사)를 원본으로 삼는다.
2. 고친 줄을 쓴다. 글자 수는 §1을 따르고, 내용은 `lyric-rules.md`를 따른다.
3. 수정 전과 수정 후 가사를 파일로 두고 비교한다:
   `python3 scripts/lyric_check.py --compare <이전.txt> <수정.txt> --title "<제목>"`
4. '고침'이 나오면 다시 쓴다(§4의 예외는 사용자에게 알린다).
5. 아래 형식으로 보여 준다.

```
**고친 줄**
| 위치 | 전 | 후 | 글자 수 |
|---|---|---|---|
| 2절 3줄 | (원래 줄) | (고친 줄) | 10 → 10 |

**수노에서**: 구간 교체(Replace Section)로 2절만 다시 만듭니다. 아래 가사를 그 구간에 넣으세요.

(그 구간의 가사 전체를 코드 블록으로)
```

- 여러 군데를 고쳤으면 가사 전체를 다시 보여 주고, 그것이 새 '현재 가사'가 된다.
- 한 줄에 수정안을 여러 개 낼 때는 2~3개까지, 모두 같은 글자 수로 낸다.

## 7. 기록

사용자가 실험 결과를 알려 주면(예: "12자 줄은 계속 몰려", "전조 문구가 먹혔어") `field-notes.md`의 '확인된 결과'에 한 줄로 적고, 저장하려면 "저장해줘"가 필요하다고 알린다.
적을 것: 날짜, 모델 버전, BPM, 해당 가사 줄, 들린 문제, 넣은 Style, 결과.
