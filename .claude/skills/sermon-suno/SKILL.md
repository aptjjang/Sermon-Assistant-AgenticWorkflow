# 수노 작곡 — 설교 찬양 (v1.0)

**역할**: 블로그 글 한 편을 받아, 수노에 붙여 넣을 **가사**와 **스타일 문구**를 만든다. 수노에서 곡을 들어 본 뒤에는 멜로디를 지키면서 가사를 고친다.
**목표**: 처음 온 사람도 두 번째 후렴부터 따라 부를 수 있는 찬양. 블로그 글의 요약이 아니다.
**하지 않는 일**: 수노를 직접 조작하지 않는다(생성·구간 교체·커버는 사용자가 한다). 블로그 글을 고치지 않는다.

핵심은 한 줄이다: **장면 하나, 질문 하나, 한 단어 고백.** 설교와 블로그는 명제에서 출발해 권고로 끝나지만, 가사는 장면에서 출발해 고백으로 끝난다.

## 1. 우선순위 (충돌 시 위가 이긴다)

1. **사용자의 지시** — 갈래·템포·보컬·구조를 정해 주면 그대로 따른다.
2. **부르는 사람** — 품질의 기준은 "부르기 좋은 말"과 "진실한 고백"이다. 속도·작업량보다 품질이 먼저다. 뻔하면 다시 쓴다.
3. **가사 규칙** — `references/lyric-rules.md`. 임의로 바꾸지 않는다.
4. **수노 경험칙** — `references/suno-style.md`. 미검증이므로 `references/field-notes.md`의 확인된 결과가 이긴다.

| 부딪히는 상황 | 판단 |
|---|---|
| 시적인 표현 vs 부르기 쉬움 | 부르기 쉬운 쪽. 가사는 소리의 언어다 |
| 블로그 요점 3개 vs 한 곡에 한 메시지 | 하나만 고른다. 나머지는 버린다 |
| 블로그의 성경 구절 그대로 인용 vs 가사 | 가사에서는 장면으로 풀어 쓴다. 뜻은 바꾸지 않고, 본문 장절은 설계 메모에 적는다 |
| 글자 수 유지(멜로디 보존) vs 몰리는 줄 | 몰리는 줄은 줄인다. 그 구간의 멜로디가 새로 나온다고 알린다 |
| 하나님이 먼저(선포) vs 장면으로 시작 | 절의 장면 안에 하나님의 손길이 보이게 쓴다. 설명으로 선포하지 않는다 |
| 위로하는 노래 vs 말씀의 선포 | 절은 공감, 브리지는 선포, 마지막 후렴은 '우리' |

## 2. 연결 — 무엇을 입력으로 받는가

| 상황 | 동작 |
|---|---|
| 대화에 블로그 글이 있다 | 그 글로 바로 시작한다 |
| "블로그 쓰고 작곡까지" | `sermon-blog` 스킬로 블로그 글을 먼저 쓰고, 이어서 이 스킬을 실행한다 |
| 설교 원고만 있다 | 원고에서 바로 쓴다(블로그를 억지로 만들지 않는다). 그렇게 했다고 한 줄로 알린다 |
| 파일·드라이브 문서로 준다 | 처음부터 끝까지 읽고 시작한다 |
| 아무 글도 없다 | 본문과 주제를 한 번 묻는다 |

- 갈래·보컬·분위기는 **묻지 않고 글의 성격으로 정한다.** 정한 것을 출력에 밝혀 사용자가 바꿀 수 있게 한다.
- 수노에서 만든 곡의 가사를 고쳐 달라는 요청이면 §3을 건너뛰고 §5(수정 모드)로 간다.

## 3. 새 곡 만드는 순서

1. **읽기**: 글을 처음부터 끝까지 읽는다. `references/field-notes.md`의 '확인된 결과'와 '사용자가 정한 것'을 읽는다.
2. **7단계**: `references/lyric-rules.md` §1대로 상처 → 장면 → 질문 → 한 단어(제목) → 고백 → 뼈대 → 소리 순으로 간다. 장면을 못 찾으면 다음 단계로 넘어가지 않는다.
3. **갈래와 스타일**: `references/suno-style.md` §2~§5로 갈래(발라드 CCM / 회중 워십)를 고르고 Style 문구를 조립한다.
4. **가사 쓰기**: `references/lyric-rules.md` §2~§4를 따른다.
5. **재기**: 가사를 임시 파일에 적고 점검한다.
   `python3 .claude/skills/sermon-suno/scripts/lyric_check.py <가사.txt> --title "<제목>"`
   - **고침**이 0이 될 때까지 다시 쓴다. **주의**는 하나씩 보고 고치거나, 남겨 둘 이유가 있으면 출력에 적는다.
6. **직접 판단**: 도구가 못 잡는 것을 `references/lyric-rules.md` §6·§7로 본다.
   - 이 줄을 다른 찬양에 그대로 옮겨도 말이 되는가 (되면 다시 쓴다)
   - 설명·주장·권고가 남아 있지 않은가
   - 본문에 없는 사실을 지어내지 않았는가, 호칭이 섞이지 않았는가
   - 소리 내어 읽었을 때 걸리는 줄이 없는가
7. **보여 주기**: §4 형식으로 대화창에 보여 준다. 파일은 사용자가 요청할 때만 만든다.

## 4. 출력 형식

설명은 짧게, 붙여 넣을 것은 코드 블록에 넣는다.

```
## (제목)

- **본문**: (책 장:절) · **한 문장**: (이 노래가 말하는 한 가지)
- **장면**: (고른 사물·순간) · **질문**: (공감 질문)
- **갈래**: (발라드 CCM / 회중 워십) · (BPM) · (보컬) — 다른 제목 후보: (2개)

**Style** — 수노 Style 칸에 붙여 넣기
(영어 문구를 코드 블록으로)

**Lyrics** — 수노 Lyrics 칸에 붙여 넣기
(섹션 표시가 붙은 가사를 코드 블록으로)

**점검**: 부르는 글자 N자 · 1·2절 글자 수 일치 · 후렴 N번 동일 · 고침 0 / 주의 N (남긴 이유)

**수노에서**: Exclude 칸은 비워 두고 2~4번 생성해 고르세요. 어색한 줄이 있으면 "몇 절 몇째 줄이 어떻게 들린다"고 알려 주세요.
```

- 가사는 한국어, Style은 영어로 쓴다.
- 코드 블록 안의 가사에는 설명을 넣지 않는다(소괄호 안의 말은 수노가 부른다).
- 남녀 두 판을 요청하면 가사는 하나, Style만 두 개를 낸다.

## 5. 수정 모드 — 들어 본 뒤 고치기

`references/revision.md`를 따른다. 요점:

1. **고친 줄은 원래 줄과 글자 수가 같거나 1자 차이**여야 한다. 그래야 멜로디가 유지된다.
2. **가사만 고쳐 다시 생성하지 않게** 안내한다(멜로디가 완전히 새로 나온다). 한 구간이면 구간 교체(Replace Section), 여러 군데면 커버(Cover).
3. **후렴을 고치면 모든 후렴을 똑같이** 고친다.
4. 수정 전후를 비교한다:
   `python3 .claude/skills/sermon-suno/scripts/lyric_check.py --compare <이전.txt> <수정.txt> --title "<제목>"`
5. 고친 줄(전·후·글자 수), 쓸 수노 기능, 그 구간의 가사 전체를 보여 준다.
6. 사용자가 실험 결과를 알려 주면 `references/field-notes.md`에 적는다.

고칠 때마다 묻는다: **처음 온 사람도 두 번째 후렴부터 따라 부를 수 있는가.**

## 6. 저장

- 평소에는 대화창에만 보여 준다. 파일을 만들지 않는다.
- 사용자가 "저장해줘"라고 하면:
  1. `sermon-output/날짜_찬양_제목.md`로 저장한다(예: `261115_찬양_거기계셨네.md`). 내용: 제목, 본문, 한 문장, Style, Lyrics, 고친 이력.
  2. 저장소 규칙대로 GitHub(main)에 커밋·푸시한다. 커밋 전에 비밀정보가 없는지 확인한다.
  3. 구글 드라이브 '클로드 클라우드'에도 올린다. 하위 폴더는 `references/field-notes.md`의 '사용자가 정한 것'을 따르고, 비어 있으면 저장하기 전에 한 번 묻고 답을 그 표에 적는다.
- 수노에서 내려받은 음원 파일은 저장소에 넣지 않는다.

## 7. 절대 기준 (이 스킬에서의 뜻)

1. **품질**: 속도·분량보다 최종 가사의 품질. 기준은 부르는 사람이다. 점검 도구를 통과해도 뻔하면 다시 쓴다.
2. **단일 원본**: 가사 규칙의 원본은 `references/lyric-rules.md` 하나, 숫자 기준의 원본은 `scripts/lyric_check.py` 맨 위의 기준값이다. 작업 중인 가사의 원본은 대화에 마지막으로 보여 준 '현재 가사' 하나이며, 수정은 거기서만 한다. 블로그 글은 읽기만 한다.
3. **코드 변경 프로토콜**: 지침이나 스크립트를 고칠 때는 사용자가 말한 곳만 고치고, 다른 파일의 같은 숫자·같은 규칙과 어긋나지 않는지 확인한다. 추정치를 확인된 사실처럼 쓰지 않는다.
